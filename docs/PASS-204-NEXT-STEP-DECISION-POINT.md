## 為什麼刻意不先寫

這個系列（Pass 194-203）已經連續多次證明：**在沒有真實資料之前
就決定修法方向，容易走偏**（Pass 197 的 threshold bug、Pass 198B
的級聯、Pass 199 的 85% 抄襲網格，都是「方向感覺合理，但沒有先看
真實資料細節」造成的）。Pass 204 的範圍會取決於：

- 如果 Pass 200 發現 `beat_this` 在已知問題點明顯優於現有 pipeline
  → Pass 204 應該是「評估把 `beat_this` 接進 Stage 3、或當作 BarStart
  V2 的新證據來源」的整合任務書，範圍會很大，需要謹慎分階段。
- 如果 Pass 200 發現 `beat_this` 表現差不多或更差 → 這條路先擱置，
  Pass 204 應該把重心放回 Pass 203 的診斷結果。
- 如果 Pass 203 發現某個證據來源的信心公式普遍只差一點點就達標
  → Pass 204 可能是針對那個具體來源的校準任務（但一定要有真實資料
  支持的具體數字，不能憑感覺調）。
- 如果 Pass 203 發現某個證據來源幾乎從未觸發、可能有 bug → Pass 204
  應該是修那個具體 bug 的任務書。
- 如果 Pass 203 發現問題是全曲普遍證據不足、不是少數幾個已知段落
  → 代表問題比原本以為的更根本，可能需要重新評估整個 BarStart V2
  這條路線值不值得繼續投入，這個決定應該由使用者做，不是 Codex。
